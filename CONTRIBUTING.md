# Contributing

1. Start from a GitHub issue with acceptance criteria and an app or area label.
2. Keep each branch and pull request focused on one coherent change.
3. Keep app-specific code in `apps/<app>`; promote code to `packages/*` only after a real cross-app reuse case is identified or an ADR justifies earlier extraction.
4. Add or update tests and include verification evidence with every pull request.
5. UI pull requests must include Storybook evidence or equivalent screenshots and recorded human approval.
6. Link the governing issue and document risks, migrations, or follow-up work.
7. Merge only after required checks and approvals pass.
